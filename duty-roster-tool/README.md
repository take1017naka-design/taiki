# duty-roster-tool

臨床工学科の **カテ待機表** を、月次の勤務割当表(Excel)から自動作成するツールです。

勤務割当表の「予／実」欄の記号と、文字色（赤字＝本人希望の不在）・セル色（濃い黄色＝本人希望で待機不可）を読み取り、
待機可否を判定したうえで、回数配分・曜日別の優先順位・連続待機の制限を満たす割り当てを探索します。

---

## 必要環境

- Python 3.10 以降
- `openpyxl`, `PyYAML`

```bash
pip install -r requirements.txt
# もしくは
pip install -e .
```

## クイックスタート

```bash
# 0) ダミーの勤務表で動作確認（実データ不要）
python -m duty_roster sample -m 2026-08 -o out/sample.xlsx
python -m duty_roster generate -s out/sample.xlsx -c config/roster.example.yaml

# 1) 手元の勤務表から設定ファイルを作る（氏名はここで初めてローカルに入る）
python -m duty_roster init-config -s data/202608.xlsx \
    --names 姓1,姓2,姓3,姓4,姓5,姓6,姓7,姓8 -o config/roster.yaml

# 2) 読み取り結果（待機可否）を確認する
python -m duty_roster check -s data/202608.xlsx -c config/roster.yaml

# 3) 待機表を作る
python -m duty_roster generate -s data/202608.xlsx -c config/roster.yaml
#    → ダウンロード/待機表/待機表_202608.xlsx
```

対象年月は勤務表の表題（例:「２０２６年　８月勤務割当表」）から自動で推定します。
推定できないときは `-m 2026-08` を付けてください。

`init-config` を `--names` なしで実行すると勤務表から姓を検出して一覧表示するので、
対象外の人が混ざっている場合は `--names` で対象者だけを指定し直してください。

## 想定する勤務割当表のレイアウト

```
行5 |          | 日   | 1  | 2  | 3  | ... | 31 |
行6 | 氏 名    | 曜日 | 土 | 日 | 月 | ... | 月 |
行7 | 31.5     | 予   | 公 | 公 |    |     |    |   ← 上段
行8 | 担当A 太郎| 実   |    |    |    |     |    |   ← 下段（氏名はどちらの行でも可）
行9 | 21.5     | 予   |―/公| 公 | 機 |     | 内視|
行10| 担当B 花子| 実   | ME |    |カテ|     |    |
```

- 日付の見出し行・氏名列・区分(予/実)列は**自動検出**します（`excel.*` で固定も可能）。
- 氏名は姓の前方一致で照合するので、設定には姓だけ書けば足ります（「担当A　太郎」に「担当A」がマッチ）。
- 上段(予)と下段(実)は運用上区別しないため、**両方をまとめてその日の勤務記号**として扱います
  （`priority.duty_source` を `予` / `実` にすると片方だけを見ます）。
- 全角英数字・半角カナ・「￣」などの表記ゆれは正規化します（`ＭＥ→ME`、`ｶﾃ→カテ`、`￣／公→―/公`）。
- 月末列の次に翌月1日以降の列があれば、月末日の「翌日の勤務内容」に使います。無ければ空白扱い（警告を出します）。

## 実装しているルール

### 待機不可の判定（全曜日共通）

| 条件 | 扱い |
|---|---|
| `公` `有` `夏` `リ` `出` `有/公` | 色に関わらず不在 → 待機不可（**黒字でも不可**） |
| **祝日・日曜**の `公` | 赤字でなければ **待機可能**（祝日は全員が「公」になるため） |
| 赤字の不在表記 | 本人希望の不在 → 待機不可（祝日でも解除しない） |
| 対象者**全員**が不在の日 | 不在による待機不可だけを解除（赤字・黄色・土日プール・バックアップ役の条件は残る） |
| `―/公`（日勤/公休） | 出勤扱い → 待機可能 |
| セルが**濃い黄色** | 本人希望 → 待機不可（予・実どちらの段でも） |
| 濃い黄色**以外**のセル色 | すべて無視（薄い黄緑・グレー・淡色など） |
| バックアップ役が不在の日 | その依存者2名も待機不可 |
| バックアップ役＋依存者2名 | 3名合計で3日以上の連続待機を禁止（ハード制約） |

> **赤字の扱いについて**：実際の勤務表では、赤字は「本人希望の不在」だけでなく
> **カテ・ABL の強調**にも使われていました。そのため既定では、赤字を不在の根拠とするのは
> 不在表記（`公` `有` `夏` など）のセルだけです。赤字のセルをすべて待機不可にしたい場合は
> 設定で `plan_codes.red_scope: any` にしてください。

### 曜日別の優先順位（翌日の勤務内容で決める）

| 曜日 | 優先順位 |
|---|---|
| 月〜木 | ① `ME` → ② `OHP` `内視` → ③ `災` `業` `労` `研修` `材料` → ④ `機` → ⑤ `OP` `アーム` 空白 |
| 金 | ① 翌日(土)に勤務がある人 → ② その他の勤務者 |
| 土 | 土日担当プールの在席者（優先順位なし） |
| **祝日** | **その日に出勤している人**（いる場合。祝日は多くが「公」になるため、実際に院内にいる人が担当する）。出勤者がいなければ通常の曜日別ルール |
| 日 | 翌日(月)が `ME` `OHP` `内視` `機` `災` `業` `労` `研修` `材料` の人。翌日が `OP` `アーム` 空白（＝手術室勤務）の人は**△（他に組めない場合の候補）** |

- 日曜は土日担当プール5名から **1人1回ずつ**（重複なし）。
- **連休のときは翌日の条件を外します**。翌日(月)が祝日、または対象者全員が不在の日は、
  翌日の勤務内容も翌日の不在も問わず、その日曜が赤字・黄色でなければ待機可能です。
- 日曜で「不可」になるのは、当日が赤字・黄色の人と、翌日(月)が不在の人だけです。
  それ以外は次の順で候補になります。
  1. **○** 制限なし
  2. **△** 前日(土)が不在（`sunday_prev_absent: 1300`）
  3. **△** 翌日(月)が手術室勤務（`sunday_next_operating_room: 2500`）
  △は「他に組めない場合の候補」なので、○で組めるならそちらを使います。
  両方に当てはまる人はコストが合算されて、いちばん後回しになります。
- 優先順位は「上から順に、候補がいなくなったら次へ」を**コストの重み**として実装しています。
  回数配分（ハード制約）と衝突したときに解が消えないようにするためで、
  実際にどの順位で採用されたかは出力の「一覧」シートに1日ずつ残ります。
- 日曜は「1人1回ずつ」の総当たりで組む都合上、優先順位が平日側のコストに
  負けないよう `weights.sunday_tier_multiplier` 倍して扱います。

### 回数配分

月の日数ごとの目標回数を `quota_by_month_length` に持ちます（合計＝月の日数）。
割り当ては**必ずこの回数どおり**になります（探索中の入れ替えが回数を変えないため）。

### 待機日の散らし方

同じ人の待機が固まらないように、次を努力目標として扱います。

- 同じ週（日曜始まり）に1人 **2回まで**（`roles.max_per_week`）
- 同じ人の間隔は **3日以上**空ける（`roles.min_gap_days`。1＝連日、2＝中1日）

超えた場合は「確認事項」シートとコンソールに一覧で出します。

### ソフト条件の強さ（衝突したときの順序）

ハード制約（待機不可の日・回数配分・バックアップ役3名の3日連続禁止）を
満たしたうえで、次の順序で妥協します。重みは `weights` で変えられます。

1. **連日待機を避ける**（`consecutive: 1500`）／同じ週の集中（`week_overload: 800`）／
   中1日など短い間隔（`short_gap: 400`）
   ※ ただし「翌日(月)が手術室勤務」の△（2500）は連日より重いので、
   　 連日を避けるためだけにこの△が使われることはありません
2. **日曜は「制限なし（○）」の候補を使う**＝前日(土)不在の候補（△）は最後の手段
   （`sunday_prev_absent: 1300`）
3. **曜日別の優先順位**（日曜は `tier` × `sunday_tier_multiplier` ＝ 第2優先で 1200）
4. 土日祝の回数の偏り（`holiday_fairness`）

つまり「制限なしの候補がいるなら、優先順位が1段下がってもそちらを使う」
「ただし連日になるなら、△の候補を使ってでも連日を避ける」という順序です。
発生した連日と、使った△は生成後にコンソールと出力ファイルに残します。

## 出力

既定の保存先は **ダウンロードフォルダの中の「待機表」フォルダ**です
（`~/Downloads/待機表`。無ければ自動で作ります）。設定で変えられます。

```yaml
output:
  directory: "~/Downloads/待機表"                # 既定
  # directory: "//サーバ名/共有/臨床工学科/待機表" # 共有フォルダに直接出す
  # directory: "~/Desktop/待機表"                # デスクトップに出す
  filename: "待機表_{year}{month:02d}.xlsx"
  # カレンダーの見た目
  calendar_column_width: 13.0
  calendar_date_row_height: 21.0
  calendar_name_row_height: 21.0
  holiday_fill: "FFFDE9E9"    # 日曜・祝日
  saturday_fill: "FFDEEBF7"   # 土曜
  weekday_fill: null          # 平日は塗らない
```

`-o` を付けるとその回だけ上書きできます。ファイル名でもフォルダでも構いません。

```bash
duty-roster generate -s 202609.xlsx -o "D:/共有/待機表"          # フォルダ指定
duty-roster generate -s 202609.xlsx -o "D:/共有/9月の待機表.xlsx" # ファイル名指定
```

出力ファイルには5シート入っています:

| シート | 内容 |
|---|---|
| 待機表 | 日曜始まりのカレンダー。日付の色は 平日=黒 / 土=青 / 日・祝=赤、セルの塗りは 日・祝=薄い赤 / 土=薄い青 |
| 一覧 | 1日ずつの 待機者・採用した優先順位・翌日の勤務・同日の他候補 |
| 集計 | 目標回数と実績、土日祝の回数、連日の数、担当日一覧 |
| 可否一覧 | 読み取り結果の目視確認用（○＝可／△＝条件付きで可／×＝不可と、その理由） |
| 確認事項 | ルール違反・要確認事項・読み取りの注意 |

ルール違反が残った場合、`generate` は終了コード 1 を返します（一覧は「確認事項」シートに出ます）。

## 設定

`config/roster.example.yaml` が全項目のサンプルです。主なもの:

| キー | 意味 |
|---|---|
| `members` | 対象者（姓） |
| `quota_by_month_length` | 月の日数ごとの目標回数 |
| `roles.backup_anchor` / `backup_dependents` | 不在時に連動して待機不可になる関係 |
| `roles.consecutive_group` / `consecutive_group_max_run` | 連続待機を制限する3名と上限日数 |
| `roles.weekend_pool` / `sunday_once_each` | 土日の担当と、日曜1人1回ルール |
| `plan_codes` | 不在記号の定義と赤字の適用範囲 |
| `priority` | 曜日別の優先順位 |
| `colors` | 濃い黄色・赤字の判定しきい値 |
| `output.directory` / `output.filename` | 待機表の保存先とファイル名 |
| `priority.holiday_prefer_working` | 祝日は当日出勤者を待機にする |
| `holidays_auto` / `holidays` | 祝日の自動計算と、追加したい休日 |
| `manual_unavailable` | 勤務表から読み取れない待機不可日を手で足す |
| `roles.max_per_week` / `min_gap_days` | 待機日の散らし方 |
| `weights` / `search` | 探索のコストと反復回数 |

## 個人情報の扱い

- **氏名を含む設定ファイル `config/roster.yaml` と `data/` `out/` `*.xlsx` `*.pdf` は `.gitignore` 済み**です。コミットしないでください。
- リポジトリに置くサンプル（`config/roster.example.yaml`、`python -m duty_roster sample`）は
  すべて仮名（担当A〜担当H）で、実名も勤務内容も含みません。
- 氏名は `init-config` で手元の勤務表から取り込む運用にしています。

## 勤務表に色が付いていない事情を足す

希望休の赤字が Excel 側に入っていないなど、勤務表から読み取れない事情は
設定に直接書けます。

```yaml
manual_unavailable:
  坂本:
    - 2026-09-20
    - {date: 2026-09-13, reason: 研究会}
```

`check` の「不可の理由」に「手動で待機不可に指定」として出ます。

## 現状の制約 / 今後

- **勤務表PDFの直接読み取りは未対応**です。PDFは実体がZIP（画像＋テキスト）のことが多く、
  文字色・セル色の判定を誤ると結果が大きく変わるため、いまは Excel を入力にしています。
  PDFしか無い月は、いったん Excel に起こしてから使ってください。
- 祝日（振替休日・国民の休日を含む）は自動計算します。院内の特別休など足したい日は
  `holidays` に書けます（`holidays_auto: false` で自動計算を止められます）。
- 優先順位に1件も当てはまらない人しか残らない日（翌日が `カテ` `ABL` `会議` `PM` `O` など）は、
  最終手段として割り当てたうえで「確認事項」に出します。
